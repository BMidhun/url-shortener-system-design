Phase 2: Caching Links Using a CDNA URL shortener is read-heavy. CDNs cache the mapping of short URLs to long URLs at edge locations, preventing traffic from hitting your Node.js server and database entirely.Understand the Flow: The CDN sits in front of Nginx. User → CDN → Nginx → Node.js.Local Simulation: Since actual CDNs (like Cloudflare or CloudFront) require a public domain, use Varnish Cache or a dedicated Nginx Caching layer in Docker to simulate edge caching locally.Set HTTP Headers: Update your Node.js code to return proper caching headers for redirect responses (e.g., Cache-Control: public, max-age=86400).Test the Cache: Run your load test again. You will notice your Node.js server logs go completely silent for repeated URL requests, while response times drop to near zero.Phase 3: Local Monitoring with Prometheus & GrafanaMonitoring gives you visibility into system health, CPU usage, and how your cache performance looks during load tests.Expose Metrics: Install a library like prom-client in your Node.js application to expose a /metrics endpoint.Spin up Prometheus: Add a Prometheus container to your Docker network. Configure its prometheus.yml file to scrape the /metrics endpoint of your Node.js app and Nginx every few seconds.Spin up Grafana: Add a Grafana container. Log into the Grafana dashboard via your browser (usually http://localhost:3000).Connect and Visualize: Add Prometheus as a data source in Grafana. Import a pre-made Node.js dashboard to view memory, CPU, and HTTP request rates in real time.
